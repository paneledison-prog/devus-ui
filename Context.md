# Devus UI: Project Context

> Living document. Updated after every change so a new session can pick up instantly.
> Last updated: 2026-10-05

## What this is
Devus UI is a React + TypeScript component library with a public homepage and a Storybook workshop. Visitors browse components, open a large preview, and copy each item as **code** or as a **master prompt**.

- Homepage: https://devus.space
- Storybook: https://storybook.devus.space
- Repo: https://github.com/paneledison-prog/devus-ui (branch `main`)
- Owner GitHub account: `paneledison-prog` (the `gh` CLI must be logged in as this account; `xnsteam-ai` is also saved on the machine and has no write access)

## Stack
React 19, TypeScript, Vite, Storybook 10 (react-vite), react-aria-components (behavior for the accessible primitives) with @internationalized/date, Shiki (code highlighting), plain CSS with design tokens (no Tailwind). No backend: everything is frontend and static.

## Commands
| Command | What it does |
|---|---|
| `npm run dev` | Vite dev server for the homepage (also `.claude/launch.json` entry `devus-ui`, port 5173, used by the desktop app preview) |
| `npm run storybook` | Storybook dev server on :6006 |
| `npm run build` | Builds the homepage into `dist/` and Storybook into `dist/storybook/` |
| `npm run preview` | Serves `dist/` locally (port 4173) |
| `npm run typecheck` | `tsc --noEmit` |

## Deployment (Vercel)
One Vercel project serves both sites. `vercel.json` sets build `npm run build`, output `dist`, and a `routes` rule that sends the host `storybook.devus.space` to `/storybook/$1` **before** the filesystem lookup (a `rewrites` rule did not work because `dist/index.html` won for `/`). Domains are registered at Vercel with Vercel nameservers, so no manual DNS records are needed; connect each domain under Project > Settings > Domains.

## Design tokens
CSS variables in `src/styles/tokens.css`: colors (`--accent`, `--default`, `--danger`, `--surface`, `--foreground`, `--muted`, `--separator`, field and shadow tokens), radii, a 4px spacing scale, Inter type scale. Dark mode is `[data-theme="dark"]` on `<html>` (homepage toggle persists to localStorage key `devus-theme`; Storybook uses the themes addon). The dark values are approximations. Scrollbars are global in src/styles/index.css: thin, transparent track, thumb = foreground at 22% (38% on hover) via --scrollbar-thumb tokens, so they follow light/dark; standard scrollbar-width/scrollbar-color plus a WebKit rounded-pill fallback. Rule: never mention the upstream design system's name anywhere in the app, code, copy or prompts.

### Accessible primitives (`src/components/Aria/`)
Sixteen components that wrap `react-aria-components` (behavior, keyboard and ARIA from the library; look from Devus tokens in `Aria.css`, classes `.ra-*`, state via the library's `data-*` attributes). `Aria.tsx` exports `AriaSelect`, `AriaComboBox`, `AriaSlider`, `AriaTabs`, `AriaAccordion`, `AriaRadioGroup`, `AriaNumberField`, `AriaMenu`, `AriaCalendar`, `AriaDateField`, `AriaTagGroup`, `AriaSearchField`, `AriaBreadcrumbs`, `AriaToggleGroup`, `AriaMeter`, `AriaModal`; `ariaItems.tsx` holds their library entries (spread into Components in `libraryItems.tsx`); one Storybook file. Code and prompts shown to users use the plain library imports. Gotcha: the large preview is a native modal `<dialog>` (top layer), so popovers and modals would render beneath it; `overlayRoot.ts` provides a context that PreviewDialog fills with the dialog element and the popover/modal components pass as `UNSTABLE_portalContainer`. Popovers only work in the large preview (tiles are covered by the open button). Dev note: `sed -i` edits can be missed by the Vite watcher on Windows; `touch` the file.

### Open a template in a new tab
Every Templates item has an "Open in new tab" action (arrow button on the tile hover actions, and a button in the large-preview footer). It opens `/?template=<slug>` (slug = lowercase name with dashes, see `src/pages/Library/slug.ts`). `src/main.tsx` reads the `template` query param and renders `src/app/TemplatePage.tsx` instead of the homepage: a slim 44px bar (back to library, template name, light/dark toggle sharing the site theme key `devus-theme`) and the template full-window. Items with `standalone` (Case study, AI workspace demo) render their responsive component at full size; items with `canvas` (the four 720x440 templates) are scaled to fit the window. Unknown slugs show a "Template not found" page. Works with the current Vercel routing because it is a query string on `/`.

## Homepage behavior
- Phone (App) large previews show a touch cursor: while a mouse or pen is over the phone the arrow is hidden (`cursor: none`) and a round translucent fingertip indicator follows the pointer and shrinks while pressed (`TouchCursor.tsx`, styles in PreviewDialog.css; real touch input is left alone; reduced motion removes the transition). Tiles in the grid keep the normal cursor.
- The large preview dialog is 2x its original size (up to 1920x1360, capped to the window minus 32px; phone dialogs up to 1720px tall). Zoom steps (75/100/150/200%) are relative to the original stage size, so 100% looks as before, only larger (a `scale` of 1 to 2 measured from the stage); phone Fit goes up to 2x.
- Templates' Code tab is a REAL file tree, not a snippet: each template has `sourceEntries` (project paths) and `src/pages/Library/sourceFiles.ts` reads the actual files with `import.meta.glob(..., { query: '?raw' })` and follows their relative imports (stories excluded) to list everything the template needs (components, CSS, `src/styles/tokens.css`). `SourceTree.tsx` shows a collapsible folder tree, per-file Copy and line count. The four small canvas templates (Landing, Dashboard, Split sign in, Settings) show `templates.tsx` (not followed) + `templates.css` + the UI components they use. Other categories keep the single-file viewer.
- App items use real code too: each App tile's preview IS a real example component in `src/components/AppUI/examples/` (e.g. `FloatingTabBar.tsx`, shared data in `data.tsx`), so the preview and the Code tab can never differ. Their Code tab is the same real file tree (the example plus every file it imports) with a `helper/<slug>/` folder, and the Master prompt ends with a reference to those real files. Helper folders exist for all 12 templates and all 19 App items (31 in total, `scripts/generate-helper.py`). When an App component changes, update its facts in the script too.
- Design bench (no new helper files; expanded `design.md`, `verify-template/SKILL.md`, `Agent.md`, `rules/05-workflow.md`, `Context.md`): every template and App item has its real design recorded as probes (box, own-text box, font size and weight, color, background, radius, relative to `#bench-root`) in `design.md` ("Bench reference", light and dark), measured from the running app at `/?template=<slug>&bench=1&theme=light|dark`, viewport 1440x900. `scripts/bench-snippet.js` (inlined into each SKILL.md) compares a running design to that reference and prints `PASS n/n probes` or the failures; `scripts/bench-reference.json` is the generator input. Agent.md requires a read receipt, the bench in both themes, and a no-hype report (rules/05-workflow.md). `TemplatePage` has a bench mode (`bench=1`, also for App items) that renders the item at natural size with no chrome. After an intended visual change, the reference must be re-measured (step 9 of the skill) and the generator re-run. Checked 2026-10-05: all 46 (23 items x 2 themes) pass against their own reference using the files an agent reads; 6 deliberate regressions (height, font size, text offset, text color in dark, missing element, radius) were all caught. A first version missed a padding change that moved text without moving the box; the text box was added for that. The bench does not see animation, hover or focus states, behavior or copy outside the probes.
- Master prompts are REAL Markdown files: `prompts/<category>/<slug>.md`, one per library item (83), and the only source of the prompt text. `libraryItems.tsx` loads them at build time with `import.meta.glob('/prompts/**/*.md', { query: '?raw', eager: true })` and fails loudly if one is missing (`LibraryItem.prompt` and `promptPath`); the old `prompt.ts` builders are gone. Each file is structured Markdown (title, Purpose/Look/Layout, API, Accessibility, Constraints/Requirements, a Design tokens table, Implementation rules, and for App items a Reference implementation list). Edit the file to change a prompt. The Master prompt tab shows the real path in a one-file tree.
- Markdown viewer (`src/components/Markdown/`): every `.md` file in the Code and Master prompt trees (prompts and all helper files) renders GitHub-style with a View / Source toggle (Source = highlighted Markdown with line numbers). Built on react-markdown + remark-gfm + remark-github-blockquote-alert + rehype-raw + rehype-sanitize + rehype-slug + rehype-autolink-headings. Supports headings with anchors, emphasis, strikethrough, links and autolinks, images, nested and task lists, aligned tables, quotes, alerts (NOTE/TIP/IMPORTANT/WARNING/CAUTION), footnotes, rules, inline code, fenced code with Shiki highlighting (tsx, ts, js, jsx, json, css, html, md, bash, yaml, diff, python, sql, xml), and sanitized HTML (details/summary, kbd, sub, sup, mark, picture). Scripts and event handlers are stripped (tested). Not supported: LaTeX math, Mermaid, emoji shortcodes. Internal `#anchor` links scroll inside the viewer.
- Every template also has a REAL helper folder at `helper/<template-slug>/` (repo root, committed Markdown), shown as `helper/` at the top of its Code tab file tree: `Context.md`, `guidelines.md`, `design.md` and `agent/` with `Agent.md` (read order, hard rules, definition of done), `rules/` (01 tokens, 02 accessibility, 03 originality, 04 code structure, 05 workflow) and `skills/` (`edit-<slug>`, `verify-template`). An agent must read and follow it before changing that template. The files are generated from the facts in `scripts/generate-helper.py` (`python scripts/generate-helper.py`; edit the facts there, then re-run and commit); `sourceFiles.ts` loads them with a raw glob of `/helper/**/*.md` and the item field `helper` (set from the template name in templates.tsx). When a template's files or features change, update its facts in the script (and its helper Context.md) in the same commit.
- Code and Master prompt tabs in the large preview use a file-viewer layout (`.ui-files` in PreviewDialog.css): a Files (1) sidebar with the highlighted file (`<Name>.tsx` / `.css`, or `PROMPT.md`), a bar with the mono file name and a Copy button, and the code or prompt below. Modeled on a skills-marketplace file viewer the user showed; the layout was recreated, nothing copied.
- Sticky header: logo, one nav link per category (Components, Blocks, Templates, Backgrounds, UI Elements, App), Storybook link, Search button (Ctrl/Cmd+K), theme toggle (contrast icon).
- Each tile: click opens the large preview dialog (compact ~45px header (15px title, slim tab pill) and ~52px footer; Preview / Code / Master prompt tabs, zoom 75/100/150/200%; phone items open taller (up to 860px) with a **Fit** zoom that auto-scales the iPhone to the stage, up to 1.2x, scaled to fit the stage at any window size, no gray box behind it); hover shows Prompt / Code copy buttons.
- Search overlay: recent searches (localStorage `devus-recent-searches`), live filter on name and prompt text, arrow keys + Enter; choosing a result scrolls to its category and opens its large preview.
