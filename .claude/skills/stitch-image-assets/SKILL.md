# Stitch image assets

The interface is always hand-built. Stitch only makes the pictures inside it, and only pictures the reference actually shows. Never use a Stitch screen as a layout, and never invent an asset the reference does not contain.

## How Stitch really behaves (measured in this repo, not guessed)

- `generate_screen_from_text` is a screen generator. Asked for "exactly ONE screen that is only a square photograph and nothing else", it answers with **two screens**: a `screenType: IMAGE` screen (the real picture) and a `DESIGN` screen (an HTML page that frames it). Take the IMAGE screen's `screenshot.downloadUrl` (a plain JPEG).
- **Size and ratio:** images come back **512px** on the long side. The ratio follows the words in the prompt: "square" gives 512x512; with no ratio and `deviceType: MOBILE` you get a tall 9:16 (286x512). Always say "square" unless you need tall.
- **No transparency.** Stitch cannot return a PNG with alpha. For cut-outs (stickers, objects) ask for the subject "on a pure flat solid light-gray (#d0d0d0) background with no shadow and no floor", then remove the background with `cutout.py` (flood fill from the border, white sticker outline).
- **Calls are slow and flaky:** 1 to 3 minutes each; "The service is currently unavailable." happens. Run prompts in parallel (8 at a time worked) and retry only the failures. A call that times out may still have created the screen (check `list_screens`).
- **IMAGE vs DESIGN:** short one-subject prompts return an IMAGE screen. A long, very detailed prompt (or a retry that adds many details) sometimes returns only a DESIGN screen. Its screenshot is still a clean render of the subject (the iridescent beer mug and the sunglasses portrait both came out that way and were the best versions), but it is 512x410 and may have black margins: crop to the non-black bounding box before use.
- The in-session MCP bridge can lose auth; `stitch_assets.py` calls `https://stitch.googleapis.com/mcp` directly with `X-Goog-Api-Key` (env `STITCH_API_KEY`, never commit it) and needs `STITCH_PROJECT`.
- A DESIGN screen is sometimes the only thing returned (e.g. a map); its HTML may be an inline SVG. That is usable as an asset, but **check it**: one SVG map drew its arterial roads with the default black fill (missing `fill="none"`). Fix such bugs in the file and say so in the assets README.

## Prompt recipe that worked

Start every prompt the same way, then describe one subject:

```
Create exactly ONE screen that is only a square photograph and nothing else: no text, no buttons, no UI, no borders.
The photo: <subject, pose, expression, clothing, setting, light>, <realistic smartphone photo | 3D render | flat illustration>, centered subject.
```

- Name the **medium** ("realistic photo", "glossy 3D emoji-style render", "flat cartoon illustration"): it decides the look more than any adjective.
- Say what must be **in frame and where** ("hands raised at the top of the picture", "face centered", "close-up").
- Give **colors as words and hex** for backgrounds ("vivid saturated bright red (#c9261f) background").
- One subject per prompt. Do not ask for several objects in one image; generate them separately.
- Avoid: text/logos in the picture, "transparent background", multiple people, brand names.

## Review loop (do not skip)

1. Write the prompt for each asset from the **reference crop**, not from the asset name. List subject, pose, framing, palette, medium.
2. Generate all assets in parallel: `python stitch_assets.py prompts.json raw 1`.
3. Make a contact sheet: `python stitch_assets.py --sheet raw sheet.png`, then **look at it** (Read the PNG) next to the reference crops.
4. For each asset decide: match or miss. A miss is wrong subject, wrong framing, wrong medium, wrong palette, or artifacts (extra text, black wedges, melted hands).
5. Rewrite only the missed prompts with the missing fact made explicit ("closer", "on a bright red background", "face fills the frame"), run attempt 2 for those names, and repeat from step 3. Stop when every asset reads as the reference at the size it is shown, or after about 3 attempts, then say honestly which ones are look-alikes.
6. Keep the winners in the repo (`src/.../assets/`) with a README that says they were generated by Stitch and lists any edit. Never hotlink.
7. Fit them to the layout in CSS, not in the file: `object-fit: cover`, `object-position`, and `transform: scale()` to crop to the part the reference shows (a 512px image shown in a 70px circle can be zoomed 2x without losing quality).

## Results log (this repo, first run of 33 prompts)

- 31 of 33 prompts matched on the first attempt (photos of animals, people and scenes; glossy 3D stickers; abstract glass art).
- Retries that were needed: `f_gold` (maroon background; adding "vivid saturated bright red (#c9261f) with soft bokeh" fixed it), `s_beer` (golden beer; "iridescent glass, pastel blue and lavender liquid" fixed it), `w_sun` (service error, then succeeded as a DESIGN screenshot).
- Failure causes seen: `"The service is currently unavailable."`, an empty response (JSON decode error), a CRLF in a names list (strip it), and prompts whose subject is tiny on a pale background.

## Parallelism and failures (second run, 32 prompts)

- Eight parallel calls plus extra ones made the service overload: 7 of 32 came back as an empty response (JSON decode error), `HTTP 502 Bad Gateway`, or "service unavailable". **Run at most 3 to 4 in parallel**, and re-run only the failures (same prompt, next attempt number) after the batch ends. Throughput was about one image per 1 to 1.5 minutes.
- Tall pictures: "tall vertical (9:16)" returns 286x512, so a full-bleed phone background is low resolution. Ask for a close-up so the subject fills the frame and you do not need to zoom, and use CSS blur for backgrounds.
- 3D objects meant to sit on cards (an ape, a cart, sneakers, achievement shapes) were generated on flat gray and cut out with `cutout.py --outline 0` (no white sticker edge).

## Quota (third run)

- Generation can answer `Resource has been exhausted (e.g. check quota).` (the script then fails with a JSON decode error on the plain-text reply). When that happens nothing can be generated for a while: build the interface, use clearly labelled stand-ins only if the user accepts them, record it in the item's gaps, and retry later. It did come back within the same session, after roughly an hour.
- A DESIGN screenshot fallback is a small framed picture (about 200px after cropping): fine for avatars and small cards, soft as a full-bleed background. Retrying with a shorter prompt did not turn it into an IMAGE screen every time; prefer to keep the first good crop instead of burning more calls.
- 24 pictures for two flows (portraits, a stage photo, 3D animal characters, a head sculpture) matched their references on the first or second attempt at 2 parallel calls.

## Known strengths and limits

- Photos of people, animals and scenes: very close to a reference described in a sentence (a groundhog in a cowboy hat, a laughing man with bleached hair, a woman in blue headphones all matched on the first try).
- Glossy 3D emoji-style objects on a flat gray background: good, and they cut out cleanly.
- Tiny objects on a pale background (a marble, a ball) come back small; ask for "filling most of the frame" or zoom with CSS.
- Exact brand characters, exact faces and exact compositions cannot be matched; they are look-alikes. Say so in the item's gaps.
- Resolution is capped at 512px. Do not use these assets larger than about 250 CSS px.

## Files here

- `stitch_assets.py`: parallel generator and contact sheet.
- `cutout.py`: background removal plus white outline for stickers.
